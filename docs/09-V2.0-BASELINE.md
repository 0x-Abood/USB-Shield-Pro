## 1. Frozen Architectural Invariants

Any code modification that alters or violates the following invariants constitutes a **breaking change** and cannot be labeled v2.0:

1. **Disk 0 / Host Boot Drive Protection**:
   - The primary system drive and physical disk 0 (`\\.\PhysicalDrive0`) are hard-coded as non-ejectable and immune to storage restrictions.
   - Any device reference resolving to Disk 0 or hosting `SystemDrive` is unconditionally rejected by `SystemDeviceSafetyGuard`.

2. **Microsoft-Native PnP Safe-Ejection**:
   - The primary eject engine is strictly `CM_Request_Device_EjectW` (`cfgmgr32.dll`).
   - Legacy filesystem dismount calls (`FSCTL_LOCK_VOLUME`, `FSCTL_DISMOUNT_VOLUME`, `IOCTL_STORAGE_EJECT_MEDIA`) are **strictly prohibited** after a PnP veto.

3. **Bounded Safe-Eject Retry Parameters**:
   - **Maximum CM Calls**: Capped at **exactly 2 calls** per physical insertion cycle.
   - **Retry Eligibility**: Permitted only on Attempt 1 returning `CR_REMOVE_VETOED` with veto type `PNP_VetoDevice` where the veto devnode correlates to the target physical disk tree.
   - **Retry Timing**: Targeted so that execution occurs at approximately **10,000 ms (10 seconds)** of total device arrival age.

4. **Storage Volume Devnode Correlation**:
   - Vetoes referencing `STORAGE\Volume` devnodes (parented under `ROOT\volmgr\0000`) correlate to the target physical disk using `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`.
   - Vetoes resolving to Disk 0 or unrelated physical disks are rejected from retry, failing closed immediately.

5. **Code 47 Verification**:
   - `CM_PROB_HELD_FOR_EJECT` (Problem 47) on the physical USB parent devnode is accepted as successful ejection.

6. **Single Enforcement Owner Architecture**:
   - When `UsbShieldService` is running in Session 0, it holds sole enforcement ownership. The GUI runs as a viewer/configuration client.
   - When the service is absent or stopped, the interactive GUI Sentinel assumes fallback ownership. Both never enforce simultaneously.

7. **Exact Baseline Recovery Guarantee**:
   - Pre-shield Windows configuration is recorded into `journal.json` **once only** before any mutation.
   - Rollback scripts (`USBShield_Restore.bat` and `USBShield_Restore.reg`) restore exact pre-shield values. If a key was absent, it is deleted; default values are never substituted.

8. **AutoPlay Guard Invariants**:
   - Toggles `DisableAutoplay` (HKCU) and `NoAutoplayfornonVolume` (HKLM).
   - Existing administrative `NoDriveTypeAutoRun` policies are read-only inspected and strictly preserved.
   - Explorer is never forcefully restarted.

9. **Production Seam Isolation**:
   - All simulation test seams (`PresenceSeam`, `DelaySeam`, `NotificationSinkSeam`, `CmRequestDeviceEjectSeam`, etc.) are guarded by `IsTestMode` and are `null` in production builds.

10. **UI TopMost Policy**:
    - All forms, dialogs, and cards maintain `TopMost = false` to avoid intrusive focus stealing.

11. **Non-Destructive Operations**:
    - Zero formatting, zero chkdsk invocations, zero partition modifications, and zero killing of host processes.

## 2. Accepted System Limitations

1. **Cooperative PnP Vetoes**: Windows Plug and Play safe removal is cooperative. If a third-party process or driver persistently holds unyielding volume handles across the 10-second retry, Windows kernel will veto both eject attempts. The software transitions safely to `FailedTerminal` and advises the user to use Windows "Safely Remove Hardware".
2. **Delayed Ejection Perception**: Because the bounded retry targets ~10s total age to allow Windows volume mounting to stabilize, devices that trigger a veto on Attempt 1 will intentionally take ~10 seconds to complete ejection.
3. **No Antivirus Capability**: USB Shield Pro is a device policy and physical port control suite. It does not scan files for malware.
