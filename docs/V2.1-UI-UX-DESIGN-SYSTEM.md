## 1. Strict v2.0 Behavioral Freeze & Scope Boundaries

The USB Shield Pro v2.1 redesign is **STRICTLY PRESENTATION ONLY**. It modernizes the visual styling, navigation layout, DPI responsiveness, and bilingual ergonomics of the existing desktop interface without altering, extending, or replacing any underlying Windows policy enforcement, device tracking, or recovery logic.

### 1.1 Non-Negotiable Invariants
1. **No Behavioral Additions**: The UI exposes only features implemented in the current production C# codebase.
2. **Explicitly Excluded / Forbidden Inventions**:
   - NO trust expiration, session trust, or editable trust attributes (the whitelist model is strictly persistent `DeviceRule` entries keyed by physical serial, instance ID, or hardware ID).
   - NO new registry policy mutations or new driver stack actions.
   - NO new diagnostic archive exporters or cryptographically signed diagnostic packages.
   - NO new activity export formats (CSV/JSON) or log virtualization engines.
   - NO new PIN behavior or emergency master PIN unlocks (the existing authentication is `PasswordManager` with `PasswordDialog` and `RecoveryKeyManager`).
   - NO configurable retry timing in the UI.
   - NO live SHA-256 integrity verification UI.
3. **Recovery Invariant**:
   - UI copy and documentation must **NEVER** state "Restore Windows default state", "Restore Clean Windows Policy Baseline", or "clears all registry blocks".
   - The authoritative v2.0 recovery invariant is: **RESTORE EXACT PRE-SHIELD BASELINE**. Absent-before values return to absent. Existing-before values return to their exact original type and data.
4. **Auto-Eject Timing Invariant**:
   - The retry schedule is **not** a flat "10s delay".
   - The authoritative specification is: **Attempt 2 targets approximately 10,000 ms TOTAL DEVICE AGE**. The actual wait duration is dynamically computed from elapsed device age (`delayMs = Math.Max(500, targetAgeMs - currentAgeMs)`).
   - Maximum 2 `CM_Request_Device_EjectW` calls; eligible target is `PNP_VetoDevice` only; fresh target/safety/trust checks are executed before Attempt 2; zero legacy FSCTL fallback after PnP failure.
5. **UI / Enforcement Separation**:
   - UI presentation components must not duplicate, reimplement, or bypass device enforcement or Windows policy logic.
   - User actions such as Lock, Unlock, Safe Eject, Trust, and Restore must call the existing authoritative application handlers/services.

## 2. Current UI/UX Audit & Gap Analysis

An exhaustive audit of the existing v2.0 desktop interface (`MainForm.cs`, `UIControls.cs`, `Localization.cs`, and screenshot artifacts) reveals solid core security functionality but significant visual, architectural, and ergonomics limitations that prevent USB Shield Pro from delivering an elite enterprise desktop experience.

### 2.1 Visual Hierarchy & Layout Deficits
- **Lack of Depth Differentiation**: Background layers (`BgDark` #0D1117, `BgPanel` #12161D, `BgCard` #161B22) differ by only 4–5 RGB points. On standard enterprise sRGB monitors, this creates a visually flat "sheet" without clear elevation cues.
- **Header Competes with Content**: The custom title bar (`_titleBar`, 44px) contains multiple saturated elements (app title, version pill, language pill, close buttons) that compete directly with the main view header for visual attention.
- **Missing Focal Anchors**: In the current Protection and Settings tabs, every section uses identical font sizing (11pt Bold for card headers) and equal visual weight, giving the user no visual hierarchy for identifying critical security states versus incidental settings.

### 2.2 The "Card Wall" Syndrome
- **Repetitive Monolithic Cards**: In `MainForm.cs`, the Protection page stacks 5–8 `RuleToggleCard` controls in a single vertical list. Each card is 78px tall with identical border treatment, identical padding, and identical switch positions.
- **Scroll Fatigue**: Because cards are tall and repetitive, essential controls (such as AutoPlay Guard and Advanced PnP rules) are pushed below the 600px viewport fold on standard 1366x768 screens, forcing constant scrolling.
- **Sub-optimal Information Density**: Empty spaces inside `CardPanel` instances waste 40% of horizontal surface on widescreen displays, while dense information (such as hardware IDs in `DeviceCardControl`) is truncated or squashed.

### 2.3 Weak Interaction Affordances & Outdated Control Usage
- **Overuse of Modal Popups**: Inspecting a connected device currently triggers `DeviceDetailsDialog` (a blocking modal dialog). The user loses context of the surrounding device list and cannot copy IDs while viewing other devices. This must be replaced with a non-blocking contextual side drawer (`AppDrawer`).
- **Hidden Advanced Settings**: Secondary driver stack controls (`_ruleStrictPnp`, `_ruleHardBlock`) are buried inside sub-panels with inconsistent collapse styling instead of clean, keyboard-accessible accordions (`AppAccordion`).
- **Static Dropdown Rendering**: The existing `DarkDropdown` uses a custom `ToolStripProfessionalRenderer` that lacks smooth hover transitions, keyboard arrow-key acceleration, and native RTL alignment support.
- **Missing Action Density**: Connected device actions (Trust, Safe Eject) occupy valuable horizontal card space as separate text buttons instead of a consolidated, clean primary action plus overflow menu (`AppMenu` / `...`).

### 2.4 Spacing & Token Inconsistencies
- **Arbitrary Margins**: Layout code in `MainForm.cs` arbitrarily mixes `8px`, `10px`, `12px`, `14px`, `15px`, `16px`, and `20px` offsets without an underlying mathematical 4px/8px modular grid.
- **Hardcoded Absolute Offsets**: Multiple controls position child labels and buttons using hardcoded coordinates (e.g., `curY += 34;`, `Left = 14; Top = 12;`), causing visual collision when font metrics vary under different DPI scaling levels or language diacritics.

### 2.5 RTL & Bidirectional Friction
- **Native WinForms Mirroring Flaws**: Global `RightToLeft = RightToLeft.Yes` causes standard WinForms controls (such as scrollbars and combo dropdown arrows) to flip erratically across Windows builds.
- **Directional Glyph Inversion**: Chevrons (`>`) and breadcrumbs in the existing UI are hardcoded strings that do not flip to `<` when switching to Arabic.
- **Asymmetrical Padding Reversal**: Left and right margins (`Padding.Left`, `Padding.Right`) are not dynamically swapped in custom-drawn controls, leading to clipped Arabic text on card edges.

### 2.6 High-DPI & Multi-Monitor Scaling Risks
- **Static Scale Caching**: `_scale = DeviceDpi / 96f` is computed once during `MainForm` construction. Moving the application window from a 100% DPI primary display to a 150% or 200% secondary 4K laptop monitor causes blurriness or layout distortion.
- **Font Object Leaks**: Custom fonts created during scaling passes are not cleanly managed in a centralized font cache, creating GDI handle strain during repeated DPI changes.

### 2.7 Control Transformation Roadmap
| Current Control | Identified Problem | Target v2.1 Transformation |
|---|---|---|
| `RuleToggleCard` (stack) | Repetitive card wall; excessive vertical height | Compact `AppToggle` row grouped under `SectionHeader` with `AppAccordion` for advanced rules |
| `DeviceDetailsDialog` (modal) | Disrupts navigation context; modal blocking | Contextual slide-out non-modal `AppDrawer` with tabbed PnP telemetry |
| Device Card Action Buttons | Cluttered horizontal footprint | Primary Action Button (`AppButton`) + Secondary Action Overflow (`AppMenu`) |
| Activity Date Filters | Basic dropdown without clear visual chips | Owner-drawn `AppDropdown` preserving native focus, keyboard, and RTL parity |
| Static Theme Class | Static hardcoded `Color` constants | Dynamic `IThemePalette` token provider with instant runtime switching |
| `DarkDropdown` | Incomplete keyboard navigation and RTL | Redesigned `AppDropdown` with full AR/EN arrow key & focus ring support |

## 3. Card-Disciplined Information Hierarchy & Navigation

Rather than eliminating cards entirely, USB Shield Pro v2.1 adopts a **card-disciplined information hierarchy**. Cards are preserved where they provide clear conceptual boundaries (summary metrics, protection posture banners, bounded high-value groups), but eliminated where they cause repetitive vertical bloat (individual settings rows, table items, navigation entries).

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ USB SHIELD PRO v2.1 — MAIN APPLICATION SHELL                                │
├───────────────┬─────────────────────────────────────────────────────────────┤
│ SIDEBAR       │ TOPBAR: System Posture Pill | Dynamic Breadcrumb | Lang/Theme│
│ (220px / RTL) ├─────────────────────────────────────────────────────────────┤
│               │ MAIN CONTENT VIEWPORT (Card-Disciplined Hierarchy)          │
│ 1. Dashboard  │ - Hero Status Card (Posture & Quick Actions)                │
│ 2. Devices    │ - Summary Metric Tiles (3 Bounded Cards)                    │
│ 3. Protection │ - Clean Data Tables & Row Stacks (No Monolithic Card Walls) │
│ 4. Trusted    │ - Contextual Slide-Out Inspector (Non-Modal AppDrawer)      │
│ 5. Activity   │                                                             │
│ 6. Recovery   │                                                             │
│ 7. Settings   │                                                             │
└───────────────┴─────────────────────────────────────────────────────────────┘
```

### 3.1 Primary Navigation Model (7 Existing Views)
1. **Dashboard (`NavDashboard`)**
   - High-level security posture summary (`ProtectionStatus` card).
   - 3 Summary Metrics: Connected Devices count, Active Rules count, Whitelist count.
   - Quick Action Toolbar: "Lock Storage", "Unlock", Temporary Access (5/15/30m with countdown).
   - Recent Activity: The 5 most recent arrival/eject events with direct drill-down.
2. **Connected Devices (`NavDevices`)**
   - Live PnP Device Grid / List (`DeviceRow` architecture).
   - Real-time arrival/removal animation.
   - Primary action: "Safe Eject" or "Add to Trusted".
   - Secondary action: Overflow menu (`...`) for Copy Hardware ID, View Details.
   - Selection opens non-modal contextual `AppDrawer` for hardware tree inspection.
3. **Protection (`NavProtection`)**
   - Security Shield Status Indicator with live policy sync status.
   - Core Policy Group: Removable Disks, Read-Only Mode, Flash Storage Sentinel (Auto-Eject), AutoPlay Guard, Portable Devices (MTP/PTP), Whitelist Mode.
   - Advanced Policy Accordion (`AppAccordion`): Strict PnP Device Installation Blocking, UsbStor Driver Service Hard Block.
4. **Trusted Devices (`NavTrusted`)**
   - Whitelist table showing authorized hardware rules (`DeviceRule`: Target Instance ID / Serial, Friendly Name, Date Added).
   - Instant search and filter.
   - One-click Revoke / Delete rule button (`TrustedDeviceRepository.RemoveRule`).
   - Empty state graphic when zero rules exist.
5. **Activity (`NavActivity`)**
   - Audit log rendered via `ActivityDateHeaderControl` and `ActivityRowControl`.
   - Filter bar: Category dropdown (All, Devices, Protection, Security, Errors), Date Range dropdown (All, Today, Last 7 Days, Last 30 Days, Custom Range with DateFrom/DateTo pickers), Search Box.
   - "Clear Activity" button with confirmation prompt.
   - Event selection opens non-modal `AppDrawer` showing full event context and metadata.
6. **Recovery (`NavRecovery`)**
   - Truthful Pre-Shield State Explanatory Card.
   - Status Card: Baseline registry entries recorded count, Mutations recorded count, Standalone package location.
   - Three authoritative v2.0 actions:
     1. "Restore Pre-Shield State" (`OnRestorePreShieldState()` -> `RecoveryManager.RestorePreShieldState`).
     2. "Open Recovery Folder" (`OnOpenRecoveryFolder()` -> Explorer in ProgramData).
     3. "Export Package (.bat+.reg)" (`OnExportRecoveryPackage()` -> `RecoveryManager.GenerateRecoveryPackage`).
7. **Settings (`NavSettings`)**
   - Access Control: Password configuration (`_pwConfigBtn`, `_pwRemoveBtn`), Master Recovery Key (`RecoveryKeyManager.GenerateNewMasterRecoveryKey()`).
   - Architecture Mode: Windows Service toggle (`_srvToggleBtn`, `ServiceManager`).
   - General Preferences: Run at Startup (`autoStartToggle`), Auto-Lock on Startup (`autoLockToggle`), Minimize to Tray on Close (`trayToggle`).
   - Personalization: 6-Theme Visual Switcher, Bilingual Language Switcher (EN/AR).
   - About & Metadata: Version 2.1, Developer credit (`x0abood`), Copyright notice.

### 5.2 Follow Windows Mode Mechanics
When `Follow Windows` is selected:
- The UI reads `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` once when Follow Windows is activated or during application startup.
- The application listens for `WM_SETTINGCHANGE` window messages.
- The UI re-reads `AppsUseLightTheme` when Windows signals a theme/settings change (with an optional fallback read only when synchronization is uncertain; no periodic registry polling timer).
- If `AppsUseLightTheme == 1`, the theme automatically applies the **Porcelain** warm light palette.
- If `AppsUseLightTheme == 0`, the theme automatically applies the **Charcoal Red** flagship dark palette.

## 7. Component System Specifications (Phased Rollout)

To minimize regression risk and avoid bloated custom WinForms code, component development is strictly separated into **Core Primitives** (built first) and **Page-Specific Components** (built only when a page blueprint requires them).

### 7.1 Tier 1: Core Primitives (Built First)
1. **`ThemeManager` & Tokens**: Centralized dynamic theme engine with `IThemePalette`.
2. **`DpiManager`**: Dynamic integer/float scaling, cached GDI fonts, and mirrored padding.
3. **`AppButton`**: Primary, Secondary, Destructive, and Ghost variants with 2px `FocusRing`.
4. **`IconButton`**: Compact toolbar button with 400ms tooltip.
5. **`AppToggle`**: High-contrast ON/OFF switch with RTL thumb shift.
6. **`AppDropdown`**: Owner-drawn/native-compatible popup dropdown (see Section 7.3).
7. **`StatusBadge`**: Semantic status pill (`Success`, `Warning`, `Danger`, `Info`, `Neutral`).
8. **`SectionHeader`**: Clean semantic section divider with optional trailing action.
9. **`AppSidebar`**: Primary vertical navigation rail with active indicator strip.
10. **`AppTopBar`**: Native-drag caption bar with status pill, theme switch, and language switch.

### 7.2 Tier 2: Page-Specific Components (Built on Demand)
11. **`AppShell`**: Double-buffered root container with drawer/overlay hosting plane.
12. **`NavigationItem`**: Keyboard-navigable sidebar row.
13. **`AppMenu` & `AppContextMenu`**: Contextual dropdown menus anchored to buttons or right-clicks.
14. **`AppAccordion`**: Collapsible container for secondary/advanced options (Protection tab).
15. **`AppDrawer`**: Non-modal contextual side inspector (see Section 8.1).
16. **`MessageBar`**: Persistent actionable inline banner.
17. **`Toast`**: Transient floating feedback notification (4.0s auto-dismiss).
18. **`SummaryMetric`**: Dashboard metric card with large tabular figures.
19. **`DeviceRow`**: Clean connected device table row replacing monolithic cards.
20. **`EmptyState`**: Subdued vector graphic with explanatory text for zero-record states.
21. **`ProtectionStatus`**: Dashboard hero defense banner with live pulse.
22. **`SearchBox`**: Real-time text filter box with search glass icon and clear button.

## 10. Actual Windows Policy & Enforcement Architecture

The v2.1 presentation layer interfaces strictly with the existing, verified backend and policy classes. No new wrapper classes or policy abstractions are introduced.

### 10.1 Real Production Classes & Roles
- **`UsbShieldPro.Windows.RegistryTransactionHelper`**: Provides write-ahead state capture and safe transaction logging before any registry modification is committed.
- **`UsbShieldPro.Windows.RemovableStoragePolicyBackend`**: Manages Group Policy registry settings under `HKLM\SOFTWARE\Policies\Microsoft\Windows\RemovableStorageDevices` (Deny_Read, Deny_Write, Deny_Execute, WPD devices).
- **`UsbShieldPro.Windows.DeviceInstallationPolicyBackend`**: Manages Device Installation restrictions under `HKLM\SOFTWARE\Policies\Microsoft\Windows\DeviceInstall\Restrictions`.
- **`UsbShieldPro.Windows.AutoPlayPolicyBackend`**: Manages AutoPlay Guard settings:
  - Sets `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\AutoplayHandlers\DisableAutoplay = 1`.
  - Sets `HKLM\SOFTWARE\Policies\Microsoft\Windows\Explorer\NoAutoplayfornonVolume = 1`.
  - **Strict Invariant**: `NoDriveTypeAutoRun` is **PRESERVED AND NEVER OVERWRITTEN** to respect existing administrator policies.
- **`UsbShieldPro.Core.ProtectionEngine`**: Orchestrates active rule evaluation, whitelist matching, and policy synchronization.
- **`UsbShieldPro.Core.StateVerifier`**: Authoritatively checks live system registry values against the desired policy state to verify policy enforcement truthfulness.
- **`UsbShieldPro.Core.RecoveryManager`**: Generates standalone rollback packages (`USBShield_Restore.bat` and `USBShield_Restore.reg`) and programmatic restoration of the exact pre-shield baseline.
- **`UsbShieldPro.Core.DeviceEnforcementLifecycleManager`**: Manages the per-device lifecycle state machine, generation IDs, and worker lease validation.

## 11. Auto-Eject State Machine & PnP Retry Contract

### 11.1 Authoritative Timing Specification
- **Initial Eject (Attempt 1)**: Attempt 1 occurs after authoritative device discovery, topology confirmation, safety validation, and policy evaluation complete for the current device generation.
- **Delayed Retry (Attempt 2)**: **Targets approximately 10,000 ms TOTAL DEVICE AGE**.
  - The actual delay duration is dynamically computed:
    `double currentAgeMs = ((Stopwatch.GetTimestamp() - t0Ticks) / Stopwatch.Frequency) * 1000.0;`
    `int delayMs = (int)Math.Max(500, (int)(10000 - currentAgeMs));`
  - It is **never** a flat 10-second wait after Attempt 1.
- **Safety Boundaries**:
  - Maximum **2 `CM_Request_Device_EjectW` calls** total per device arrival cycle.
  - Delayed retry is scheduled **ONLY** if Attempt 1 fails with `PNP_VetoDevice` on the target device tree.
  - Before Attempt 2 executes, fresh target resolution, safety guard re-check, trust re-check, and active policy re-check are authoritatively performed.
  - **Zero legacy FSCTL fallback**: Legacy `FSCTL_LOCK_VOLUME` / `FSCTL_DISMOUNT_VOLUME` fallback is strictly 0 after PnP failure.
