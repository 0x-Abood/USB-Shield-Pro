## 1. Executive Summary & Migration Principles

This document defines the strict, phased engineering roadmap for modernizing the presentation layer of USB Shield Pro from v2.0 to v2.1. 

The redesign is **PRESENTATION ONLY**. It transforms the visual styling, navigation layout, DPI responsiveness, and bilingual ergonomics of the existing desktop interface without altering, extending, or replacing any underlying Windows policy enforcement, device tracking, or recovery logic.

### 1.1 Non-Negotiable Engineering Invariants
To preserve release integrity, all UI refactoring must adhere to these absolute rules:
1. **Zero Behavioral Changes**: Under no circumstances shall USB arrival detection, PnP monitoring, device state tracking, or driver interaction logic be altered.
2. **Preserve Exact Pre-Shield Recovery**:
   - The UI and codebase must **NEVER** imply or perform "Restoring Windows defaults" or "clearing all registry blocks".
   - The authoritative v2.0 recovery invariant is: **RESTORE EXACT PRE-SHIELD BASELINE**.
   - Absent-before registry values are deleted; existing-before values are restored to their exact original type and data.
3. **Preserve Auto-Eject State Machine & Timing**:
   - Attempt 1 occurs after authoritative device discovery, topology confirmation, safety validation, and policy evaluation complete for the current device generation.
   - **Attempt 2 targets approximately 10,000 ms TOTAL DEVICE AGE** (`delayMs = Math.Max(500, targetAgeMs - currentAgeMs)`). It is **not** a flat 10-second delay.
   - Maximum 2 `CM_Request_Device_EjectW` calls; eligible target is `PNP_VetoDevice` only; fresh target/safety/trust/policy checks; zero legacy FSCTL fallback after PnP failure.
4. **Preserve Policy Backend Invariants**:
   - Windows policies are managed strictly by existing classes: `RegistryTransactionHelper`, `RemovableStoragePolicyBackend`, `DeviceInstallationPolicyBackend`, and `AutoPlayPolicyBackend`.
   - `NoDriveTypeAutoRun` is **PRESERVED AND NEVER OVERWRITTEN** to respect existing administrator policies.
5. **No Invented Features**:
   - No trust expiration, session trust, or editable trust attributes.
   - No CSV/JSON audit export or log virtualization engines.
   - No driver stack whitelisting or block setup class actions.
   - No diagnostic archive export or cryptographically signed bundles.
   - No new PIN behavior or emergency master PIN unlocks (authentication remains `PasswordManager` with `PasswordDialog` and `RecoveryKeyManager`).
   - No configurable bounded retry timing.
   - No desktop toast notifications setting or SHA-256 live integrity verification UI.
6. **Bilingual Parity**: Every new or refactored component must support both English (LTR) and Arabic (RTL) with 100% string coverage in `Localization.cs`.
7. **No Regressions**: The 147-test automated verification suite (`TestRunner.exe --test-harness`) must pass with 100% success at the conclusion of every implementation phase.

### Phase 1: Dynamic Token & Theme Engine
- **Goal**: Decouple visual styling from static hardcoded colors and establish a DPI-aware rendering pipeline.
- **Implementation Tasks**:
  1. **Create `ThemeTokens.cs`**:
     - Define `IThemePalette` interface exposing all surface, border, text, accent, and semantic color tokens.
     - Implement the 6 concrete palette classes:
       - `CharcoalRedPalette` (Signature — Rich Crimson `#C62D42`)
       - `MidnightPalette` (Royal Blue `#2F6FEB`)
       - `GraphitePalette` (Cool Steel Slate `#64748B`)
       - `PorcelainPalette` (Deep Indigo / Slate Blue `#1E40AF`)
       - `CloudPalette` (Cobalt Blue `#1D64EC`)
       - `FollowWindowsPalette` (Reads `AppsUseLightTheme` on activation/startup and synchronizes via `WM_SETTINGCHANGE` without periodic polling).
     - Create static `ThemeManager` with `ActivePalette` and `ThemeChanged` event.
  2. **Backward Compatibility Bridge in `Theme.cs`**:
     - Retain existing `Theme.BgDark`, `Theme.AccentBlue`, etc., as computed properties redirecting to `ThemeManager.ActivePalette` so existing controls continue functioning without disruption during rollout.
  3. **Create `DpiManager.cs`**:
     - Implement high-precision integer scaling: `ScaleInt(int baseValue)`, `ScaleFloat(float baseValue)`, and `ScalePadding(Padding basePadding)`.
     - Implement cached GDI font provider: `GetFont(TypographyToken token)`.
     - Implement bidirectional padding helper: `MirrorPadding(Padding p, bool isRtl)`.
  4. **Configure `App.config`**:
     - Add `AppContextSwitchOverrides` and `DpiAwareness = PerMonitorV2` to ensure the .NET 4.8 runtime enables advanced DPI scaling.
- **Verification**:
  - Unit tests verifying color values for all 6 themes.
  - Verify switching themes triggers `ThemeChanged` without memory leaks.
  - Regression check: `TestRunner.exe --test-harness` -> 147/147 PASS.

## 3. Risk Mitigation & Fallback Strategy

| Identified Risk | Severity | Preventive Mitigation Strategy |
|---|---|---|
| **WinForms RTL Scrollbar Flipping** | High | Avoid native WinForms `RightToLeft.Yes` container wrapping where known OS bugs exist. Use custom `DarkScrollPanel` with manual docking alignment. |
| **GDI Font Handle Leaks** | High | Centralize all `Font` and `Brush` creation in `DpiManager` and `ThemeManager` with strict disposal and caching patterns. |
| **DPI Blur on Monitor Shift** | Medium | Handle `WM_DPICHANGED` natively; do not rely on static `DeviceDpi` cached in constructors. |
| **Accidental PnP Logic Mutation** | Critical | UI presentation components must not duplicate, reimplement, or bypass device enforcement or Windows policy logic. User actions such as Lock, Unlock, Safe Eject, Trust, and Restore must call the existing authoritative application handlers/services. |
| **Arabic Text Clipping** | Medium | Ensure all Arabic label containers have `AutoEllipsis = true` and `DpiManager` adds 15% line-height padding for diacritics. |
